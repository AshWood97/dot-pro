# dot-pro

一个 Codex 技能，用于协调 ChatGPT 网页 Pro、Dot 和本地 Codex 完成获授权的协作任务。它也支持用户明确要求的网页 Deep Research 与图像工作流。

对代码任务，已连接兼容 Git MCP 的 Pro 优先直接读取固定版本并交付代码；不同 Pro 会话独立审查，由一位 Dot 集成批次、执行必要检查，再将获批的子 PR 实际合入同 fork 的批次。Codex 按精确的版本和审查结果机械接收汇总交付，并按授权完成公司侧集成。具体分工以用户选择和实际能力为准。

## 安装

在 Codex 中使用自带的 `$skill-installer`，例如：

> 使用 `$skill-installer` 从 `AshWood97/dot-pro` 的 `skills/dot-pro` 安装技能。

安装后在下一轮对话中使用 `$dot-pro`。安装内容和说明见 [技能正文](skills/dot-pro/SKILL.md) 与 [MCP 接口参考](skills/dot-pro/references/git-mcp.md)。仓库根目录还提供便携插件元数据 [plugin.json](plugin.json)；推荐优先通过 skill-installer 安装技能。

## 准备与使用

1. 按任务需要准备可用的 ChatGPT Pro 会话、Dot 和 Codex 原生浏览器控制能力。多个账号由使用者指定或按任务上下文选择，提交前确认当前账号、会话和模型。
2. 若要求 Pro 直接向 Git 交付，需要用户已批准的兼容 MCP 服务和该会话实际可用的连接。服务地址与认证由使用者提供；本仓库不附带 Git MCP 服务端，也不自动安装或部署服务。
3. 按 [OpenAI 官方自定义 MCP 接入说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)在 ChatGPT 中添加服务、按服务配置设置认证并安装，然后在会话中用 `@` 选择连接。服务更新后，在已安装插件的详情中刷新工具清单，并确认当前 Pro 会话实际发现批次准备、审查和合并工具，再派发批次。根据当前界面和授权处理写入确认。
4. 给出项目、目标、版本或工作区来源、预期交付和授权范围。技能会固定 manifest 与导出提交，按需要读取源码，通过兼容工具提交任务分支并创建或续更 PR。

示例请求：

> 使用 `$dot-pro`，让已连接 Git MCP 的 Pro 基于指定固定版本实现改动，由另一 Pro 审查，Dot 集成批次并执行必要检查，Codex 接收获批的汇总 PR。

如 Pro 会话没有连接或缺少工具，技能会说明实际缺口，并在获授权时将具体源码上下文和补丁交给 Dot 执行；不会把其他模型或普通浏览说成 Pro 的 Git 写入能力。可用账号、工具、模型及配额均以当前实际状态为准。

## 能力与边界

- 曾在一个连接兼容服务的 Pro 会话中验证：读取固定版本、提交并再次更新同一分支、创建和续更同一 PR，以及读取交付状态。这只说明当次接入与原有交付流程可用，不能推断新增审核或批次合并已由 Pro 实测，也不代表任意账号、服务或业务测试均已通过。
- 一次真实服务 API 演练验证了两个子 PR 在同 fork 批次中合并、旧 head/base 批准被拒绝、共享改动保留和增量读取，并创建了仍未合并的汇总草稿 PR；这次由宿主调用 API，并非 Pro 会话实测或公司业务验收。随后空响应处理修复通过定向测试并部署，已合并 PR 的重入返回成功；修复后尚未重新实测新合并。
- [接口参考](skills/dot-pro/references/git-mcp.md)描述固定版本、任务分支、批次、审查及同 fork 批次合并接口。它不提供任意 shell、测试、构建、Issue 管理、上游同步镜像合并或部署。
- 批次汇总 PR 保持开放供本地接收；独立审查记录绑定实际 head/base。服务使用共享 Gitea bot，审查者标签来自自报，独立性由 Pro 会话和任务分工保证。公司凭据仅留在本地。
- 任务 fork 的推送权限不等于 PR 合并权限；由服务 owner 在获授权的任务 fork 范围配置所需能力。PR 的合并标记不代替实际代码审查和项目检查。
- 写入结果不明确时，先查询原任务的交付状态，再决定是否重试；同一任务保留固定基线和实际分支。Azure PR 不等于公司仓库已接收、合并或上线。
- Deep Research 使用网站的实际研究模式并返回可取得的报告与来源；图像任务使用网站生成或编辑并取回实际原图。不可用时报告限制。
- 技能本身不会授权发送资料、安装连接、提交代码、合并或部署。遵守任务授权、项目规则和实际平台提示，只交付已完成且可核对的结果。
